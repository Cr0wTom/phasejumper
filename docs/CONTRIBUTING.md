# Contributing

## How work is organised

Work is split into tickets (spec §9). One ticket = one branch = one pull request = one rollback unit.

- Branch from `main`; commit messages start with the ticket: `T0x: <what>`.
- Build only what the ticket lists. If something is unclear or you must deviate from the spec, say so in the PR under a **DEVIATION** heading with the reason.
- The PR description states what was tested and the rollback step (normally: revert the merge commit).

## Checks

Every PR must pass:

```bash
pnpm lint && pnpm typecheck && pnpm test && pnpm build
```

Plus the acceptance tests listed on the ticket. CI runs the same checks on every pull request.

Code rules:

- TypeScript strict; no `any`; no `console.log` in shipped code.
- Every source file starts with the Apache-2.0 header.
- The engine (`packages/engine/src`) is pure: no I/O, no network, no `Date.now()`, no randomness. Lint enforces this.
- Dates and times use `temporal-polyfill`; store UTC instants, convert at the edges.
- No server, analytics, cookies, third-party scripts or CDN fonts — the site is static files.
- New user-facing strings live in `packages/engine/src/copy.ts` (engine) or `apps/web/src/messages.ts` (web).

## Golden fixtures and snapshots

The engine's reference plans live in `packages/engine/test/fixtures/`. Inputs are written by hand; `.expected.json` files are generated by `vitest -u` and never edited.

Never run `vitest -u` to make a test pass; run it only when the PR intentionally changes engine output, and describe the diff in the PR.

A change that alters engine output also bumps `ENGINE_VERSION`.

## Words we don't use

PhaseJumper is general wellness information, not medical advice, and never a prescription. User-facing text (UI, engine copy, README, terms and privacy) must not contain these words; CI will enforce the list:

> treat, treatment, cure, diagnos-, prescri-, therapy, therapeutic, disorder, patient, dose, dosage, mg, notification, reminder, guarantee, clinically proven, medical-grade

Melatonin appears only as a timing window for people who say they already use it — never an amount or a product. Don't mention other jet-lag apps anywhere in the project.
